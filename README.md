# Argument Mining for Film Reviews: воспроизведение бейзлайна

Воспроизводим эксперимент из статьи Serbina, Borisova, Rabinovich, *Argument Mining for Film Reviews* (Dialogue 2026).
Датасет: [otipl2125/film_review_argumentation](https://huggingface.co/datasets/otipl2125/film_review_argumentation), CC-BY-4.0.

## Постановка из статьи

- Вход: только `content`. Цели: `NEW_grade3` (stance) и `arg_label` (premise), по 3 класса в каждой.
- Разбиение 70/15/15 со стратификацией по `arg_label`: 2296 / 492 / 492.
- Энкодер и две параллельные линейные головы, лосс равен сумме двух CE. Обучение идёт 2 эпохи.
- Метрика: macro-F1, bootstrap с 1000 итераций, 95% ДИ по подгруппам (век, рейтинг, конгруэнтность).

В статье не указаны lr, batch size, max length и seed разбиения. Здесь взяты стандартные значения:
lr 2e-5, batch 16, max_length 512, warmup 10%, weight decay 0.01, seed 42.
Поэтому состав тестовой выборки отличается от авторского, и корректнее сравнивать результаты по ДИ, а не по точным числам.

## Запуск

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python src/train.py --model DeepPavlov/rubert-base-cased
.venv/bin/python src/train.py --model ai-forever/ruRoberta-large
```

Результаты сохраняются в `runs/<model>_seed<seed>/`: `metrics.json`, `predictions.csv`, `report.csv`.
Пересчитать отчёт по готовым предсказаниям: `python src/evaluate.py runs/<run>/predictions.csv`.

Разведочный анализ датасета (таблицы печатаются и складываются в `analysis/`):

```bash
.venv/bin/python src/analyze.py --tokenizer DeepPavlov/rubert-base-cased
```

## Анализ данных

Полный разбор — в `src/analyze.py`, ниже то, что влияет на интерпретацию результатов.

**Явная оценка в тексте.** 56% отзывов содержат конструкцию вида «8 из 10», «10 баллов из 10»,
«7/10», и у 98.5% из них она стоит в последних 15% текста. Извлечённое число в 92.8% случаев
равно колонке `grade10`, из которой выведен таргет `NEW_grade3`. То есть в `content` лежит сам
источник метки.

Насколько этого достаточно без всякой модели — правило «число ≤4 → Bad, ≤6 → Neutral, иначе Good»
на 1818 отзывах с оценкой:

| Задача | Accuracy | macro-F1 |
|---|---|---|
| stance | 0.803 | 0.718 |
| premise | 0.687 | 0.647 |

Для сравнения, дообученная rubert-base-cased даёт 72.44 stance на полном тесте. Поэтому прогон
с флагом `--strip-grade` (маркер вырезается в `data.strip_grade`, остаточных вхождений 0,
удаляется в среднем 1.28 слова) — не улучшение, а измерение: сколько модель берёт из самой
аргументации, а не из финального балла.

**Баланс классов.** stance 34/23/43% (Bad/Neutral/Good), premise 23/35/41%. Метрика — macro-F1,
лосс — невзвешенный CE, и слабее всего идёт именно `Neutral`: recall 43% у rubert-base и 52%
у ruRoberta на stance.

**Длины.** Максимум 305 токенов для rubert и 356 для ruRoberta, при `max_length=512` обрезка
не срабатывает ни разу. Значение 320 безопасно и освобождает память под больший батч.

**Шум.** 32% текстов приходят с padding по краям (снимается `strip`), 60% содержат склейки
предложений вида `Темнота.Чужие`, 1.3% — двойные пробелы внутри. HTML, URL и буквы «ё» нет.

**Сплит.** `split_dataset` стратифицирует только по `arg_label`; распределение stance держится
на seed 42 случайно. Сплит не групповой: 95.5% фильмов из теста есть в трейне, у одного автора
до 18 отзывов.

**Не баг:** 452 неуникальных `review_id` — это переиспользованный идентификатор у разных отзывов
о разных фильмах (307 id встречаются больше чем у одного фильма), тексты уникальны.
Дедуплицировать по `review_id` нельзя.

## Без явной оценки в тексте

Те же гиперпараметры плюс `--strip-grade`, результат в `runs/<model>_seed42_nograde/`:

```bash
.venv/bin/python src/train.py --model DeepPavlov/rubert-base-cased --strip-grade
```

macro-F1 на тесте (n=492), в скобках 95% bootstrap ДИ.

| Модель | Stance | Premise |
|---|---|---|
| rubert-base-cased | 65.60 (61.6–69.6) | 68.42 (64.2–72.3) |
| ruRoberta-large | 72.93 (69.2–76.9) | 74.27 (70.2–78.0) |

Сравнивать пересечение ДИ здесь нельзя: тестовая выборка у обоих прогонов одна, ошибки моделей
скоррелированы. Правильный тест — парный bootstrap, он же `--compare`:

```bash
.venv/bin/python src/evaluate.py runs/rubert-base-cased_seed42/predictions.csv \
    --compare runs/rubert-base-cased_seed42_nograde/predictions.csv
```

Сколько теряется при удалении оценки (бейзлайн минус прогон без оценки):

| Модель | Задача | Δ macro-F1 | 95% ДИ разницы | p |
|---|---|---|---|---|
| rubert-base-cased | stance | **+6.85** | (+2.61, +10.95) | **0.001** |
| rubert-base-cased | premise | +0.47 | (−3.32, +4.10) | 0.404 |
| ruRoberta-large | stance | +1.29 | (−1.78, +4.52) | 0.208 |
| ruRoberta-large | premise | −0.62 | (−3.45, +2.17) | 0.655 |

Модели ведут себя по-разному. rubert-base значимо теряет на stance около 7 пунктов: балл в тексте
равен `grade10`, источнику `NEW_grade3`, и база держалась именно на нём. ruRoberta-large не теряет
ничего ни на одной задаче — она читает аргументацию, а не финальную цифру. На premise не теряет
никто, что ожидаемо: для `arg_label` балл предсказывает хуже (macro-F1 правила 0.647 против 0.718).

Из-за этого утечка искажала и сравнение моделей между собой:

| Данные | Задача | ruRoberta − rubert | 95% ДИ | p |
|---|---|---|---|---|
| бейзлайн | stance | +1.77 | (−2.53, +6.06) | 0.215 |
| без оценки | stance | **+7.33** | (+2.82, +11.97) | **0.002** |
| бейзлайн | premise | +4.76 | (+0.16, +9.21) | 0.022 |
| без оценки | premise | +5.85 | (+1.50, +10.55) | 0.007 |

На исходных данных преимущество ruRoberta по stance статистически неразличимо (p=0.215): цифра
в конце отзыва доступна обеим моделям и подтягивает слабую до уровня сильной. После удаления
утечки разрыв вырастает вчетверо и становится значимым. То есть бейзлайн из статьи недооценивает
разницу между энкодерами ровно там, где она есть.
