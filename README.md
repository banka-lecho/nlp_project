# Argument Mining for Film Reviews: воспроизведение бейзлайна

Воспроизводим эксперимент из статьи Serbina, Borisova, Rabinovich, *Argument Mining for Film Reviews* (Dialogue 2026).
Датасет: [otipl2125/film_review_argumentation](https://huggingface.co/datasets/otipl2125/film_review_argumentation), CC-BY-4.0.

## Постановка из статьи

- Вход: только `content`. Цели: `NEW_grade3` (stance) и `arg_label` (premise), по 3 класса в каждой.
- Разбиение 70/15/15 со стратификацией по `arg_label`: 2296 / 492 / 492.
- Энкодер и две параллельные линейные головы, лосс равен сумме двух CE. Обучение идёт 2 эпохи.
- Метрика: macro-F1, bootstrap с 1000 итераций, 95% ДИ по подгруппам (век, рейтинг, конгруэнтность).

В статье не указаны lr, batch size, max length и seed разбиения. Здесь взяты стандартные значения:
lr 2e-5, batch 16, max_length 512, warmup 10%, weight decay 0.01, seed 42.
Поэтому состав тестовой выборки отличается от авторского, и корректнее сравнивать результаты по ДИ, а не по точным числам.

## Запуск

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python src/train.py --model DeepPavlov/rubert-base-cased
.venv/bin/python src/train.py --model ai-forever/ruRoberta-large
```

Результаты сохраняются в `runs/<model>_seed<seed>/`: `metrics.json`, `predictions.csv`,
`val_predictions.csv`, `report.csv`. В `predictions.csv` лежат и вероятности классов, из них
считаются калибровка и ординальные метрики. Пересчитать отчёт по готовым предсказаниям:
`python src/evaluate.py runs/<run>/predictions.csv`.

Флаги сверх постановки статьи — каждый по умолчанию выключен, так что команды выше
воспроизводят постановку бейзлайна. Единственное отличие от прежних прогонов: `content`
теперь всегда проходит `strip()` (32% текстов приходят с padding по краям), иначе ступень
`none` отличалась бы от остальных ступеней лестницы не только тем, что вырезано.

| Флаг | Что делает |
|---|---|
| `--redact {none,grade,last-sentence,tail15,first-half}` | лестница удаления текста, накопительная |
| `--group {movie_name,author}` | групповой сплит: фильм (автор) целиком в одной выборке |
| `--head {softmax,corn}` | ординальная голова CORN вместо номинального softmax |
| `--class-weights balanced` | взвешенный лосс под macro-F1 |
| `--pooling {cls,mean}` | усреднение по токенам вместо `[CLS]` |
| `--select-by {last,mean}` | брать лучшую эпоху по val, а не последнюю |
| `--split-seed`, `--seed` | сплит и инициализация разводятся независимо |

Разведочный анализ датасета (таблицы печатаются и складываются в `analysis/`):

```bash
.venv/bin/python src/analyze.py --tokenizer DeepPavlov/rubert-base-cased
```

## Анализ данных

Полный разбор — в `src/analyze.py`, ниже то, что влияет на интерпретацию результатов.

**Явная оценка в тексте.** 56% отзывов содержат конструкцию вида «8 из 10», «10 баллов из 10»,
«7/10», и у 98.5% из них она стоит в последних 15% текста. Извлечённое число в 92.8% случаев
равно колонке `grade10`, из которой выведен таргет `NEW_grade3`. То есть в `content` лежит сам
источник метки.

Насколько этого достаточно без всякой модели — правило «число ≤4 → Bad, ≤6 → Neutral, иначе Good»
на 1818 отзывах с оценкой:

| Задача | Accuracy | macro-F1 |
|---|---|---|
| stance | 0.803 | 0.718 |
| premise | 0.687 | 0.647 |

Для сравнения, дообученная rubert-base-cased даёт 72.44 stance на полном тесте. Поэтому прогон
с флагом `--redact grade` (маркер вырезается в `data.strip_grade`, остаточных вхождений 0,
удаляется в среднем 1.28 слова) — не улучшение, а измерение: сколько модель берёт из самой
аргументации, а не из финального балла.

**Баланс классов.** stance 34/23/43% (Bad/Neutral/Good), premise 23/35/41%. Метрика — macro-F1,
лосс — невзвешенный CE, и слабее всего идёт именно `Neutral`: recall 43% у rubert-base и 52%
у ruRoberta на stance.

**Длины.** Максимум 305 токенов для rubert и 356 для ruRoberta, при `max_length=512` обрезка
не срабатывает ни разу. Значение 320 безопасно и освобождает память под больший батч.

**Шум.** 32% текстов приходят с padding по краям (снимается `strip`), 60% содержат склейки
предложений вида `Темнота.Чужие`, 1.3% — двойные пробелы внутри. HTML, URL и буквы «ё» нет.

**Сплит.** `split_dataset` стратифицирует только по `arg_label`; распределение stance держится
на seed 42 случайно. Сплит не групповой: 95.5% фильмов из теста есть в трейне, у одного автора
до 18 отзывов.

**Не баг:** 452 неуникальных `review_id` — это переиспользованный идентификатор у разных отзывов
о разных фильмах (307 id встречаются больше чем у одного фильма), тексты уникальны.
Дедуплицировать по `review_id` нельзя.

## Воспроизведение (RTX 4090, bf16)

macro-F1 на тесте (n=492), среднее ± стандартное отклонение по пяти seed'ам обучения.
Сплит у всех прогонов один (`--split-seed 42`), меняется только инициализация.

| Модель | Stance | Premise | Stance (статья) | Premise (статья) |
|---|---|---|---|---|
| rubert-base-cased | 72.44 ± 1.04 | 69.39 ± 1.20 | 71.31 | 75.00 |
| ruRoberta-large | 74.11 ± 1.44 | 74.61 ± 0.83 | 75.56 | 78.10 |

Stance воспроизводится у обеих моделей, premise у rubert-base устойчиво ниже авторских
75.00 — разрыв в 5.6 пункта при разбросе 1.2 не объясняется seed'ом. У ruRoberta-large
premise сходится (74.61 против 78.10 — 3.5 пункта), stance тоже (74.11 против 75.56).

Числа на Mac M4 (MPS) отличаются: там прогоны идут в fp32, на 4090 включается bf16-autocast,
и это разные численные режимы, а не разные реализации. Сравнивать модели между собой можно
только внутри одного железа; `aggregate.py` печатает колонку `device` и предупреждает,
если в сравнение попали прогоны с разных устройств. Дальше везде числа с 4090.

## Без явной оценки в тексте

Те же гиперпараметры плюс `--redact grade`:

```bash
.venv/bin/python src/train.py --model DeepPavlov/rubert-base-cased --redact grade
```

| Модель | Stance | Premise |
|---|---|---|
| rubert-base-cased | 64.71 ± 1.26 | 68.01 ± 0.34 |
| ruRoberta-large | 72.39 ± 1.33 | 74.12 ± 1.03 |

Сравнивать пересечение ДИ здесь нельзя: тестовая выборка у обоих прогонов одна, ошибки моделей
скоррелированы. Внутри одного seed правильный тест — парный bootstrap (`--compare`),
а по набору seed'ов дельта считается покомпонентно (`aggregate.py --delta`):

```bash
.venv/bin/python src/aggregate.py --delta rubert-base-cased rubert-base-cased_nograde
```

Сколько теряется при удалении оценки (бейзлайн минус прогон без оценки), по совпадающим
seed'ам:

| Модель | Задача | Δ macro-F1 | Разброс | По seed'ам |
|---|---|---|---|---|
| rubert-base-cased | stance | **+7.73** | ± 0.49 | +7.40 +7.96 +8.48 +7.50 +7.30 |
| rubert-base-cased | premise | +1.39 | ± 1.30 | +3.27 −0.11 +0.56 +1.86 +1.37 |
| ruRoberta-large | stance | **+1.71** | ± 0.46 | +1.60 +2.20 +1.09 +2.12 +1.56 |
| ruRoberta-large | premise | +0.49 | ± 1.27 | +1.75 −1.22 +1.06 −0.46 +1.33 |

Обе модели теряют на stance, но на порядок по-разному: 7.73 против 1.71, то есть в 4.5 раза.
Обе дельты положительны на всех пяти seed'ах и втрое-впятнадцатеро больше своего разброса,
так что обе реальны. На premise не теряет никто: дельты 1.39 ± 1.30 и 0.49 ± 1.27 с
отрицательными значениями среди seed'ов.

Это уточняет вывод, который на одном seed выглядел иначе. Раньше ruRoberta показывала
+1.29 при 95% ДИ (−1.78, +4.52), то есть «не теряет ничего». Пять seed'ов показывают, что
теряет — стабильно, на всех прогонах, просто мало. Правильная формулировка не «ruRoberta
не смотрит на балл», а «ruRoberta опирается на него вчетверо меньше».

Почему разница именно на stance, понятно из данных: балл в тексте равен `grade10`, из
которого выведен таргет `NEW_grade3`. Для `arg_label` тот же балл предсказывает хуже
(macro-F1 правила 0.647 против 0.718), и обе модели на premise к нему равнодушны.

Из-за этого утечка искажала и сравнение моделей между собой:

| Данные | Задача | ruRoberta − rubert | Разброс | По seed'ам |
|---|---|---|---|---|
| бейзлайн | stance | +1.67 | ± 1.58 | +0.73 +2.13 +0.17 +4.19 +1.12 |
| без оценки | stance | **+7.68** | ± 1.19 | +6.53 +7.89 +7.56 +9.57 +6.86 |
| бейзлайн | premise | +5.22 | ± 1.15 | +3.80 +5.13 +6.95 +4.74 +5.46 |
| без оценки | premise | +6.12 | ± 0.71 | +5.33 +6.24 +6.45 +7.06 +5.50 |

На исходных данных преимущество ruRoberta по stance равно +1.67 при разбросе ±1.58 —
неотличимо от нуля, на одном seed из пяти оно вообще +0.17. Цифра в конце отзыва доступна
обеим моделям и подтягивает слабую до уровня сильной. После удаления утечки разрыв
вырастает вчетверо, до +7.68 ± 1.19, и становится больше разброса в шесть раз.

То есть бейзлайн из статьи недооценивает разницу между энкодерами ровно там, где она есть:
на stance он показывает «модели примерно равны», хотя на самом деле сильная модель лучше
на 7.7 пункта, а слабая просто списывает ответ из текста. На premise, где списать нечего,
разрыв виден сразу и почти не меняется: +5.22 против +6.12.

### Разброс по seed'ам

Разброс от инициализации на выборке из 492 примеров сопоставим с самим измеряемым эффектом,
поэтому прогон повторяется на нескольких seed'ах. `--split-seed` при этом фиксирован:
тестовая выборка у всех прогонов одна, и парный bootstrap остаётся применим.

**Прогон невоспроизводим побитово даже при фиксированном seed.** Инициализация детерминирована
(веса голов совпадают побитово, первые три шага дают одинаковый лосс до восьмого знака), но
с четвёртого шага лоссы расходятся на ~1e-7: на MPS порядок суммирования в редукциях не
гарантирован. За 144 шага × 2 эпохи это накапливается примерно в пункт macro-F1. На CUDA
то же самое по умолчанию, но там лечится `torch.use_deterministic_algorithms(True)` и
`CUBLAS_WORKSPACE_CONFIG`; на MPS такого рычага нет.

Практическое следствие: одиночный результат нельзя перепроверить — только пересчитать
и получить другое число. Один и тот же эксперимент на MPS, тот же seed 42, дважды:

| Задача | Прогон 1 | Прогон 2 |
|---|---|---|
| stance | +6.85, ДИ (+2.61, +10.95), p=0.001 | +8.52, ДИ (+4.39, +12.68), p=0.000 |
| premise | +0.47, ДИ (−3.32, +4.10), p=0.404 | +2.71, ДИ (−0.78, +6.25), p=0.066 |

Вывод по stance устойчив, а по premise «уверенно ничего» (p=0.40) превратилось в «на границе»
(p=0.066) от простого перезапуска. Bootstrap-ДИ меряет шум выборки, но у точечной оценки есть
собственный шум перезапуска сопоставимой величины, и одиночный ДИ его не видит.

Величина разброса зависит от железа. На Mac (fp32, MPS) rubert-base по stance давал
72.20 ± 2.43 с размахом 6.14 пункта; на 4090 (bf16, CUDA) — 72.44 ± 1.04. Среднее то же,
разброс вдвое меньше. Пять seed'ов — слишком мало, чтобы надёжно оценивать само σ, так что
трактовать это как «bf16 стабильнее» не стоит; практический вывод другой — σ надо мерить
на том железе, на котором считаются результаты, а не переносить из прошлых прогонов.

```bash
./run_server.sh seeds
.venv/bin/python src/aggregate.py
.venv/bin/python src/aggregate.py --delta rubert-base-cased rubert-base-cased_nograde
```

`--delta` считает разницу по совпадающим seed'ам: сравниваются прогоны с одинаковой
инициализацией, а не одно число с другим. `aggregate.py` отдельно предупреждает о прогонах
на уровне случайного угадывания — один разошедшийся запуск иначе незаметно утаскивает
среднее конфигурации и раздувает σ.

### Лестница удаления текста

`--redact grade` отвечает на вопрос «держится ли модель за балл», но не отвечает на вопрос
«а что она вообще читает». Лестница накопительная, каждая ступень убирает строго больше
предыдущей, и начиная с `grade` явной оценки в текстах не остаётся ни у одного отзыва
(таблица — `analysis/redaction_ladder.csv`):

| Ступень | Что остаётся | Слов в среднем |
|---|---|---|
| `none` | всё | 103.5 |
| `grade` | текст без числовой оценки | 102.2 |
| `last-sentence` | без оценки и без последнего предложения | 86.6 |
| `tail15` | без оценки и без последних 15% символов | 86.4 |
| `first-half` | без оценки, только первая половина | 50.5 |

Смысл в том, что падение ниже уровня `grade` уже нельзя списать на утечку балла: это
потеря аргументации.

macro-F1 дообученных моделей по ступеням, в скобках падение относительно `none`:

| Ступень | rubert stance | rubert premise | ruRoberta stance | ruRoberta premise |
|---|---|---|---|---|
| `none` | 72.44 ± 1.04 | 69.39 ± 1.20 | 74.11 ± 1.44 | 74.61 ± 0.83 |
| `grade` | 64.71 (−7.73) | 68.01 (−1.38) | 72.39 (−1.72) | 74.12 (−0.49) |
| `last-sentence` | 63.07 (−9.37) | 66.89 (−2.50) | 70.53 (−3.58) | 73.38 (−1.23) |
| `tail15` | 59.68 (−12.76) | 68.78 (−0.61) | 70.82 (−3.29) | 74.23 (−0.38) |
| `first-half` | 54.40 (−18.04) | 62.36 (−7.03) | 68.52 (−5.59) | 70.02 (−4.59) |

Три вещи видны сразу.

**Разрыв между моделями растёт вниз по лестнице.** На `none` это 1.67 пункта stance,
на `first-half` — 14.12. Чем меньше поверхностных зацепок в тексте, тем сильнее решает
качество энкодера.

**Premise держится там, где stance рушится.** У rubert-base срезание хвоста стоит
12.76 пункта stance и 0.61 премиса. Аргументация размазана по всему тексту, позиция
сосредоточена в концовке — и это ровно то, что показал пробинг замороженных представлений.

**Дообучение усиливает зависимость от хвоста, а не ослабляет её.** У пробинга падение
rubert stance выходило на плато после `grade` (−4.35, −4.83, −4.61), у дообученной модели
продолжает расти (−7.73, −9.37, −12.76). Замороженные представления просто не умеют
извлечь из концовки столько, сколько извлекает дообученная голова.

### Групповой сплит

В исходном сплите 95.5% фильмов из теста встречаются в трейне, так что обобщение на новый
фильм не измеряется. `--group movie_name` убирает пересечение полностью. Стратификации при
групповом сплите нет и баланс классов в тесте плывёт (`analysis/group_splits.csv`), поэтому
это отдельный режим оценки, а не ещё одна строка в общей таблице.

```bash
.venv/bin/python src/train.py --model DeepPavlov/rubert-base-cased --group movie_name
```

Группировка по автору почти ничего не меняет: 2666 авторов на 3280 отзывов, медиана — один
отзыв на автора, и пересечение по фильмам остаётся 97.7%.

Результат оказался обратным ожидаемому — качество не падает, а слегка растёт:

| Модель | Задача | Случайный сплит | Групповой | Разница |
|---|---|---|---|---|
| rubert-base-cased | stance | 72.44 ± 1.04 | 73.13 ± 1.46 | +0.70 ± 1.86 |
| rubert-base-cased | premise | 69.39 ± 1.20 | 70.56 ± 2.15 | +1.16 ± 2.58 |
| ruRoberta-large | stance | 74.11 ± 1.44 | 75.38 ± 0.79 | +1.28 ± 1.22 |
| ruRoberta-large | premise | 74.61 ± 0.83 | 77.75 ± 1.05 | +3.13 ± 1.85 |

Пересечение фильмов между train и test, которое выглядело изъяном сплита, качество
не завышало. Объяснение в природе разметки: таргет — позиция конкретного рецензента
и структура его аргументации, а не свойство фильма. Увидев в трейне двадцать отзывов
на «Бойцовский клуб», модель не узнаёт метку двадцать первого: они там разные.
Утечки через фильм нет, в отличие от утечки через балл в тексте.

Разницу нельзя читать как выигрыш: тестовая выборка другая (476 против 492), баланс
классов в ней сдвинут, а трейн больше (2463 против 2296). Корректный вывод — отрицательный
и от этого не менее полезный: групповой сплит не меняет картину, и результаты статьи
не нужно дисконтировать из-за негруппового разбиения.

### Ординальная голова и веса классов

Классы упорядочены: Bad < Neutral < Good. Совместная таблица показывает, что крайние
путаницы редки (47 + 32 пары Bad↔Good против 398 + 59 соседних), но номинальный softmax
считает ошибку Bad→Neutral и Bad→Good одинаковой. `--head corn` кодирует порядок явно
(CORN, Shi et al. 2021): вместо трёх независимых классов две условные вероятности
P(y > Bad) и P(y > Neutral | y > Bad).

Отдельно: метрика — macro-F1, а лосс — невзвешенный CE, и слабее всего идёт самый редкий
класс. `--class-weights balanced` согласует лосс с метрикой.

```bash
.venv/bin/python src/train.py --model DeepPavlov/rubert-base-cased --head corn
.venv/bin/python src/train.py --model DeepPavlov/rubert-base-cased --class-weights balanced
```

Отчёт теперь печатает и ординальные метрики: QWK (штраф растёт как квадрат расстояния между
классами), MAE и долю ошибок через класс.

Разница с бейзлайном по совпадающим seed'ам:

| Вариант | Модель | Задача | Δ macro-F1 | Разброс |
|---|---|---|---|---|
| `--head corn` | rubert-base-cased | stance | −0.47 | ± 2.34 |
| `--head corn` | rubert-base-cased | premise | −0.05 | ± 1.44 |
| `--class-weights balanced` | rubert-base-cased | stance | −0.31 | ± 0.62 |
| `--class-weights balanced` | rubert-base-cased | premise | **−2.36** | ± 1.23 |
| `--class-weights balanced` | ruRoberta-large | stance | **+2.14** | ± 1.58 |
| `--class-weights balanced` | ruRoberta-large | premise | −0.57 | ± 0.98 |

**CORN не даёт ничего.** У rubert-base обе дельты в пределах разброса. Гипотеза была в том,
что ординальная голова поможет там, где softmax считает ошибку Bad→Good такой же, как
Bad→Neutral, — но крайние путаницы и так редки, поэтому исправлять почти нечего.

**Веса классов работают по-разному у разных моделей.** У ruRoberta-large stance растёт
на 2.14 (76.25 ± 1.19 — лучший stance во всей таблице, выше авторских 75.56), у rubert-base
premise падает на 2.36 на всех пяти seed'ах. Взвешивание помогает только той модели,
у которой есть запас: слабую оно уводит от крупных классов, ничего не давая взамен.

**CORN на ruRoberta-large неустойчив.** На seed 44 обучение разошлось: macro-F1 0.199
при NLL 1.072 ≈ ln 3, то есть выход почти равномерный. Один такой прогон утащил среднее
конфигурации до 63.67 ± 24.51. Остальные четыре seed'а дают +1.92, +0.34, −0.80, −0.42,
то есть тот же ноль, что и у rubert-base. `aggregate.py` теперь отдельной строкой
показывает прогоны на уровне угадывания, чтобы такое не уходило в среднее незамеченным.

### Отбор эпохи по val

В статье берётся последняя из двух эпох. У ruRoberta-large на второй эпохе stance растёт
(0.741 → 0.754), а premise падает (0.757 → 0.742) — то есть «последняя эпоха» систематически
занижает одну из задач. `--select-by mean` берёт эпоху с лучшим средним val macro-F1.
По умолчанию оставлено `last`, чтобы воспроизведение оставалось воспроизведением.

### Калибровка

`predictions.csv` теперь хранит и вероятности классов, `val_predictions.csv` — то же на
валидации. Температура подбирается на val и применяется к test; macro-F1 при этом не
меняется, потому что argmax инвариантен к температуре.

```bash
.venv/bin/python src/evaluate.py runs/<run>/predictions.csv --calibrate
```

По всем 80 прогонам картина однородная: T лежит в 1.05–1.51, то есть модели слегка
переуверены, но не сильно — за две эпохи на 2.3k примерах они не успевают переобучиться.
ECE падает примерно вдвое, с 0.03–0.10 до 0.02–0.07. Заметно выше T у ruRoberta-large
на premise (до 1.51) — самая уверенная пара «сильная модель, размазанный сигнал».
Исключение — групповой сплит, где T около 1.0 и иногда ниже: на тесте из невиданных
фильмов модель и так не переуверена.

### Линейный пробинг

Самый дешёвый способ проверить историю с утечкой: энкодер заморожен, дообучения нет, поверх
его представлений учится логистическая регрессия (C подбирается на val).

```bash
.venv/bin/python src/probe.py --model DeepPavlov/rubert-base-cased
.venv/bin/python src/probe.py --model ai-forever/ruRoberta-large
```

macro-F1 на тесте, в скобках изменение относительно `none` (`analysis/probe_*.csv`):

| Ступень | rubert stance | rubert premise | ruRoberta stance | ruRoberta premise |
|---|---|---|---|---|
| `none` | 60.66 | 65.62 | 67.48 | 69.69 |
| `grade` | 56.31 (**−4.35**) | 64.11 (−1.51) | 65.77 (−1.71) | 70.22 (+0.53) |
| `last-sentence` | 55.83 (−4.83) | 62.16 (−3.46) | 62.57 (−4.91) | 68.52 (−1.17) |
| `tail15` | 56.05 (−4.61) | 61.99 (−3.63) | 62.95 (−4.53) | 69.68 (−0.01) |
| `first-half` | 51.52 (−9.14) | 58.52 (−7.10) | 58.14 (−9.34) | 65.39 (−4.30) |

Здесь видно ровно то же расхождение между моделями, что и при дообучении, и без дообучения:
на первой ступени rubert теряет на stance 4.35 пункта, а ruRoberta — 1.71. У дообученных
моделей та же пара — −6.85 (p=0.001) и +1.29 (незначимо). То есть асимметрия не создаётся
дообучением: она уже лежит в представлениях, дообучение её только усиливает.

Дальше по лестнице модели сходятся: к `first-half` обе теряют около 9 пунктов на stance.
Это и есть смысл накопительности — ниже уровня `grade` оценки в тексте нет ни у кого, и
одинаковое падение у обеих моделей означает, что теряется общая для них аргументация,
а не утечка.

Отдельно стоит отметить поведение задач. stance у rubert проседает на одном удалённом числе
и дальше выходит на плато: убрать ещё 16 слов хвоста стоит примерно ноль. premise так себя
не ведёт ни у одной модели — он деградирует монотонно вместе с длиной текста. Сигнал stance
сосредоточен в балле, сигнал premise размазан по аргументации.

Стоимость на Mac M4: 6 минут для rubert-base, 35 для ruRoberta-large — вся лестница целиком,
против примерно десяти часов, если гнать те же пять ступеней дообучением.

## Прогоны на сервере с 4090

Разработка ведётся локально, на сервере только `git pull` и запуск. План прогонов лежит
в репозитории файлом, чтобы его не приходилось набирать руками:

```bash
git clone https://github.com/banka-lecho/nlp_project.git && cd nlp_project
./run_server.sh setup
./run_server.sh seeds
```

`./run_server.sh` без аргументов печатает список этапов с оценками времени. Этапы идут
по убыванию важности и независимы друг от друга; `--skip-existing` внутри означает, что
любой этап можно прервать и запустить заново — готовые прогоны пропускаются.

| Этап | Что считает | Прогонов | 4090 |
|---|---|---|---|
| `seeds` | 5 seeds × 2 модели × {`none`, `grade`} | 20 | ~55 мин |
| `group` | групповой сплит по фильму | 10 | ~30 мин |
| `heads` | CORN и веса классов | 20 | ~55 мин |
| `ladder` | нижние ступени лестницы дообучением | 30 | ~85 мин |
| `probe` | линейный пробинг | — | ~10 мин |
| `summary` | все сводные таблицы | — | секунды |

Перед каждым этапом проверяется, что torch видит CUDA: без этого прогоны идут часами
вместо минут, и лучше упасть сразу. Датасет и веса моделей скачиваются автоматически,
`data/` в репозитории нет.

Начинать нужно с `seeds`. Сейчас у ruRoberta-large ровно один прогон, её собственный
разброс неизвестен, и вся таблица сравнения моделей держится на этом допущении.
Этот же этап пересчитывает rubert-base на CUDA: существующие числа получены на MPS,
а сравнивать модели между собой корректно только в пределах одного железа —
`aggregate.py` предупреждает, если в сравнение попали прогоны с разных устройств.

Результаты остаются на сервере: `runs/` в `.gitignore`. Забирать имеет смысл
`runs/*/metrics.json` и `analysis/*.csv` — это килобайты.

## Состояние: что посчитано, а что нет

Посчитано на RTX 4090 — 80 прогонов, около полутора часов:

- 5 seeds × 2 модели × 5 ступеней лестницы
- групповой сплит по фильму, 5 seeds × 2 модели
- ординальная голова и веса классов, 5 seeds × 2 модели
- линейный пробинг обеих моделей по всей лестнице (числа с Mac, на CUDA те же)
- калибровка по всем прогонам

Код готов, прогонов нет:

- **Разброс по `--split-seed`** — сейчас все прогоны делят одну тестовую выборку. Это
  правильно для парных сравнений, но означает, что к разбросу по инициализации не добавлен
  разброс по составу выборки.
- **CORN на ruRoberta-large без развала** — нужен прогон seed 44 с меньшим lr, иначе
  конфигурация непригодна для сравнения.
- **5-fold CV** вместо одного сплита.
- **Взаимодействие задач**: совместная 9-классовая голова, обуславливание premise на stance,
  обучаемые веса задач.
- **Focal loss и logit adjustment** — из пункта про дисбаланс сделаны только веса классов.
- **LLM-ярус**: zero-/few-shot и QLoRA поверх декодера, с оценкой и без.
- **Атрибуции** на расходящихся примерах.
